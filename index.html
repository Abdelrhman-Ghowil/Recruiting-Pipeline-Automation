Build Milestones

Structured 4-phase delivery — click each phase to see exactly how we implement it, step by step.

Phase 01

Foundation Build

GHL Environment · ATS Connection · Field Mapping

6–8 hrs
▾

We start with zero-to-one: a clean GHL sub-account configured exactly around your recruiting process. Before any automation fires, every structural element — pipeline, fields, tags, users — must be precisely defined. This phase ends when a test candidate record travels from ATS all the way into GHL with accurate field data.

01
GHL Sub-Account Setup & Configuration

Create or configure the GHL sub-account for recruiting. Set up recruiter user seats with correct role permissions (admin, recruiter, view-only). Configure timezone, business hours, and brand identity (logo, colors) so all outbound communications look professional from day one.

GHL Sub-account User roles & permissions Brand settings Business hours config
02
Pipeline Stages Construction

Build the full recruiting pipeline inside GHL Opportunities, mirroring your predefined stage map exactly. Each stage gets a clear name, color code, and win/loss designation. We configure probability weights for reporting and set up stage-transition rules so records can only move in valid sequences.

12+ pipeline stages Stage color coding Win/loss rules Transition validation Probability config
03
Custom Contact Fields & Opportunity Templates

Map every ATS data point to a GHL custom field — job title applied for, source channel, screening score, interview date, recruiter assigned, candidate notes. Build the Opportunity template so new records auto-populate with the right field structure. Set up tags taxonomy (source tags, status tags, disqualification reason tags).

Custom field mapping Opportunity templates Tag taxonomy Data schema design
04
ATS Webhook Configuration

Inside your ATS, configure outbound webhooks to fire on key events: new application submitted, application status changed, candidate disqualified. We document the exact JSON payload structure your ATS sends and validate it using Zapier's built-in webhook inspector to confirm field names and data types.

ATS webhook setup Event triggers defined JSON payload validation Zapier catch hook
05
Initial Field Mapping & Data Validation

Build the first Zap: ATS Webhook Trigger → GHL Contact Create/Update. Map every ATS field to its corresponding GHL custom field. Run 5–10 live test submissions through the ATS and verify each record appears in GHL with correct data. Fix any field-type mismatches (date formats, phone number formatting, empty field fallbacks).

Field-to-field mapping Format normalization Live test submissions Error fallback rules

Phase 02

Automation Logic

Zap Configuration · AI Screening · Workflow Rules · Auto-Tagging

10–12 hrs
▾

The brain of the system. This phase wires together every conditional rule, routing decision, and automated action — so the pipeline runs itself. We build multi-step Zaps with error handling, configure all GHL workflow automations, and integrate and calibrate the AI phone screening tool end-to-end.

01
Multi-Step Zap Architecture

Expand the initial Zap into full multi-step flows. Each Zap includes: Filter step (only process relevant events), Formatter step (clean/transform data), Action step (create/update GHL contact + opportunity), Error path (Zapier Paths for failed records with Slack/email alert to admin). Build separate Zaps for: new application, status change, disqualification, and screening completion events.

Zapier Paths (branching) Filter + Formatter steps Error path + admin alert 4+ distinct Zap flows Retry logic config
02
GHL Workflow Automation Rules

Inside GHL Workflows, build trigger-action chains for every stage transition. When a contact enters "New Application" stage → assign to recruiter queue, apply source tag, start nurture sequence. When contact moves to "Screening" stage → trigger AI phone call. When "Qualified" → pause nurture, start scheduling sequence. Each workflow gets an "if/else" branch for handling edge cases.

Stage-trigger workflows If/Else branching Recruiter assignment rules Sequence start/stop logic
03
AI Phone Screener Integration

Connect the AI voice screening tool to GHL via its API or webhook. Configure the trigger: when a candidate reaches the "AI Screening" pipeline stage, GHL workflow calls the AI tool's API with the candidate's phone number and the job-specific question script. Upload and calibrate the screening script — question order, tone, disqualification triggers, and response capture fields.

AI tool API connection Script upload & calibration Stage-trigger setup Question flow config
04
Screening Results Capture & Routing

Configure the AI tool's outbound webhook — after each screening call, it sends results (score, transcript summary, individual answer data) back to GHL via a Zapier Zap or direct GHL webhook. Map results to custom fields on the GHL contact. Build conditional routing: score ≥ threshold → move to "Schedule Interview" stage; score below → "Needs Manual Review"; call failed → retry workflow fires.

Results webhook receiver Score threshold routing Transcript field mapping Retry on call-fail logic Manual review flagging
05
Automated Tagging & Recruiter Alerts

Build the full tagging system: source tags applied on entry, qualification tags applied after screening, stage-progression tags updated on every move. Configure recruiter notification workflows — instant in-GHL alerts when a candidate qualifies, Slack or email notification with candidate summary when manual review is needed, daily digest of pipeline movement for team leads.

Auto-tagging rules GHL internal notifications Slack/email alerts Daily digest workflow

Phase 03

Engagement & Calendar

SMS/Email Sequences · Google Calendar · No-Show Recovery

8–10 hrs
▾

The candidate-facing layer. We deploy every pre-written messaging template into timed, conditional sequences — then build the full interview scheduling ecosystem on top of Google Calendar. By the end of this phase, a candidate can go from receiving a screening result to a confirmed interview slot without any human intervention.

01
SMS & Email Sequence Deployment

Import all pre-written message templates into GHL's email and SMS builders. Build timed drip sequences for each pipeline stage: initial application confirmation (immediate), follow-up if no response (Day 2), re-engagement nudge (Day 4), final attempt (Day 7). Each sequence has a stop trigger — if the candidate responds or books, all pending messages are cancelled automatically.

Template import Timed drip logic Auto-stop on response SMS compliance config Unsubscribe handling
02
Google Calendar Integration

Connect GHL's calendar system to each recruiter's Google Calendar via OAuth. Configure availability windows — which days, hours, and meeting types are bookable. Set buffer time between interviews (15 min default), max interviews per day per recruiter, and advance booking windows (min 4 hours, max 14 days ahead). Sync is bi-directional: existing Google Calendar blocks are respected.

OAuth calendar link Availability windows Buffer time rules Bi-directional sync Max-per-day limits
03
Self-Scheduling Workflow Build

When a candidate qualifies, a GHL workflow triggers an SMS + email containing a personalised scheduling link (GHL calendar widget). The link shows only real available slots. Upon booking: candidate receives confirmation email + Google Calendar invite with video/phone link. Recruiter receives instant alert with candidate name, role, and interview details. GHL pipeline stage auto-updates to "Interview Scheduled".

Scheduling link generation Auto-confirmation email Google Cal invite Stage auto-advance Recruiter alert
04
Pre-Interview Reminder Cadence

Build a 3-touch reminder sequence that triggers automatically after booking: 24 hours before (email + SMS with interview details and prep tips), 2 hours before (SMS only — concise confirmation with dial-in/link), 30 minutes before (SMS only — "Your interview is in 30 minutes" with a quick link to reschedule if needed). Each reminder includes cancellation/reschedule options to reduce ghost-no-shows.

T-24h email + SMS T-2h SMS T-30min SMS Reschedule links Cancellation handling
05
No-Show Recovery Protocol

Configure a GHL workflow that fires exactly 15 minutes after a scheduled interview slot if the candidate has not been marked "Completed" by the recruiter. Recovery sequence: immediate SMS ("We missed you — here's a link to rebook"), follow-up email at T+1 hour with a sense of urgency, final attempt at T+24 hours before auto-archiving the record with a "No-Show" tag. Recruiter receives alert at each failed contact attempt.

T+15min trigger 3-touch recovery sequence Reschedule link Auto-archive at T+24h No-show tag applied

Phase 04

Testing & Reporting

End-to-End QA · Dashboards · Documentation · Handoff

8–10 hrs
▾

Nothing ships without it passing the gauntlet. We run the entire system through structured test scenarios, simulate every edge case (failed calls, no responses, duplicate submissions), build the reporting dashboards, and produce complete handoff documentation so your team can operate and modify the system independently.

01
Full End-to-End Pipeline Testing

Run a minimum of 20 live test candidates through the complete pipeline — from ATS application submission to confirmed interview. Test each pathway: qualified candidate, disqualified candidate, non-responsive candidate, candidate who reschedules, and no-show candidate. Verify every Zap fires, every GHL workflow triggers, every message sends, and every stage transition completes correctly.

20+ test candidate runs 5 scenario pathways Full audit log review Zap history validation GHL activity log check
02
Edge Case & Fail-Safe Testing

Deliberately break things to confirm the system handles failure gracefully. Test: duplicate application submission (same email), webhook delivery failure (Zapier retry), AI screening call failure (no answer, call dropped), candidate unsubscribes mid-sequence, recruiter calendar fully blocked. Verify error alerts fire, records land in correct fallback states, and no data is lost or duplicated.

Duplicate handling Webhook retry test Call failure recovery Unsubscribe compliance Data integrity check
03
Analytics Dashboard Build

Build GHL reporting dashboards with four core views: Pipeline Throughput (applications in → interviews out, by week/month), Stage Conversion Rates (% moving from each stage to the next — identifies bottlenecks), Recruiter Efficiency (interviews booked per recruiter, response times, no-show rates), and Time-to-Interview (average days from application to confirmed interview slot).

Pipeline throughput view Stage conversion funnel Recruiter KPI cards Time-to-interview metric Weekly auto-refresh
04
Bug Fixes & Optimization Pass

After test runs, address every identified issue with a documented fix log. Optimize Zap performance (reduce unnecessary steps, remove redundant filters). Review message delivery rates and tune send-time settings. Check AI screener question flow for any awkward transitions based on test call recordings. Confirm all GHL workflows have correct enrollment filters to prevent double-triggering.

Fix log documentation Zap optimization Delivery rate review Double-trigger prevention Call recording review
05
Documentation & Team Handoff

Deliver a complete operations guide covering: system architecture overview (how all platforms connect), Zap-by-Zap breakdown (what each does and when), GHL workflow map (visual diagram of all automation rules), how to add a new recruiter, how to update message templates, how to pause/resume sequences, and a troubleshooting FAQ for the 10 most likely issues. Recorded walkthrough video included.

Architecture overview doc Zap reference guide GHL workflow map Admin how-to guides Recorded walkthrough Troubleshooting FAQ
